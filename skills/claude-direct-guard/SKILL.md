# Claude 目标 IP 防直连

把用户选择的保护范围落实为可核验、可回滚的 Windows 防火墙配置。优先回答当前状态和实际覆盖范围；不要把“规则存在”“请求被拦”“长期不会消失”混成一个结论。

## 先确定本次任务

- 用户只问解释或当前状态时，解释或只读核验，不借机修改网络设置。
- 从当前会话识别最终授权：目标 IP 阻止、整程序强制代理、Clash 分流是不同方案。采用用户最后明确的范围，不把旧授权或案例偏好应用到新任务。
- “只拦 Claude 相关 IP”表示按目标网段匹配，不是阻止整个 Chrome。默认保持当前 Clash 模式、节点、TUN、系统代理、浏览器策略及客户端代理环境变量。
- 当其他过滤条件及有效防火墙配置文件匹配时，Program=Any 的目标 IP 规则可覆盖浏览器、Claude 桌面版、Claude Code 及其他连接到同一目标网段的程序；它不识别“Claude”这个产品名。
- 创建或更新规则已被授权时，完成具体变更即可，不反复要求同一范围的确认。Windows 管理员提权是独立执行要求。启停其他软件服务、永久停用服务、卸载软件不是普通 IP 规则变更的一部分。

## 核对网段和连接路径

阅读 [范围与案例](references/scope-and-case.md)，其中地址是有日期的来源记录，不能当永久真值。新建或调整范围前按需要重新查官方文档；已明确指定范围的任务保留用户选择并说明来源。

1. 区分官方服务入站地址、Anthropic 服务器发起请求的出站地址、第三方推荐的大网段。官方 API/Console 的说明不能直接扩大为全部 Claude 网页、认证、附件、遥测服务的承诺。
2. 静态网段内换 IP 仍受规则覆盖；移到范围外不会自动纳入。扩大网段增加覆盖，也可能影响该段内其他服务；静态名单不等于永久防直连。
3. Clash 分流只处理它接管的连接。Windows 目标 IP 阻止规则独立于 Clash，但不会自动指定代理路线。
4. 显式本地代理下，应用通常连接本机监听端口，代理核心再连接代理服务器；核心若改为直连被封目标，也应受同一系统规则约束。真实目的 IP 的透明 TUN 路径可能先被防火墙拦截，不能保证所有代理方式都正常。
5. 本机禁用 IPv6 不代表远端代理出口不能使用 IPv6。区分本机直连地址、代理出口地址与 DNS 解析服务器；网站出现 IPv6 或“可能泄露”不足以单独确认绕过代理。

## 用户自有的 Clash 分流规则

随附 [22 条规则扩展示例](examples/clash-verge-rules.yaml)，其策略组名为 `🤖AI服务`。用户要求添加、检查或迁移分流时阅读 [Clash 分流说明](references/clash-routing.md)。它使用 `prepend / append / delete` 规则扩展格式，不是完整订阅或全局 Merge。

先核对目标订阅里的代理组、关联扩展和规则模式；保留其他应用的选路。文件只包含匹配规则，不包含节点或订阅。共享第三方域名会影响其他使用这些域名的产品，不能把它们的地址当成 Claude 独占 IP 加入防火墙。

分流示例仍沿用原有 `/23`、`/48`，本案例防火墙经用户要求扩为 `/21`、`/32`。用户请求迁移或发布规则，不等于批准切换本机模式或重新部署网络。

## 实施或维护

实际修改时阅读 [Windows 操作与排查](references/windows-firewall.md)。只修改目标明确的规则；先记录它们的名称、存储、过滤条件和将被修改字段，再实施。已有规则优先原地更新，避免不必要的删除重建。

- 目标 IP 阻止通常是 Outbound / Block / Enabled，覆盖需要的防火墙配置文件、程序和协议；不要通过全局默认出站阻止、整个 Chrome 封禁或封锁共享 CDN 大网段替代用户选择。
- 防火墙配置文件若关闭，不得仅凭规则存在声称生效。开启前先记录 Enabled、DefaultOutboundAction、相关既有阻止规则及本地规则合并策略：开启会让原有策略同时生效，可能影响浏览器或代理核心。评估后按现有授权处理，不能把开启防火墙当成只影响新增两条规则的操作。
- 保留精确回滚数据。回滚只恢复本轮修改的字段或移除本轮新建的规则，不重置整个防火墙，不覆盖无关配置。
- 不把本地代理密钥、订阅地址、认证配置、账号历史或完整机器配置复制进报告或技能。

## 核验与答复

使用只读脚本检查明确的规则名称：

```powershell
& '<skill-dir>\scripts\Get-DestinationGuardState.ps1' -RuleName @('实际 IPv4 规则名称','实际 IPv6 规则名称')
```

脚本读取 PersistentStore、ActiveStore、地址/程序/协议过滤条件，以及有效防火墙配置文件的开启状态、默认出站策略和本地规则合并设置。它只查询指定规则，不代表已经排除既有规则的影响。它不修改网络，不发起网站请求，不申请管理员权限，不把读权限失败当成规则消失。按环境权限在真实宿主机执行。

检查实际范围与批准范围等价，规则 Enabled、Outbound、Block，程序、协议、配置文件符合要求。配置存在性检查不等于端到端验证。

有刚创建即消失的历史时，做一次短时、只读的延后复核；报出时间和结果，勿把短期保留写成永久稳定。无新失败时不要无限轮询或反复安装。

需要连接验证时，优先只读规则证据和用户已有测试。只有在用户接受可能产生直连请求的前提下进行目标连接测试；使用无登录、无 Cookie、无令牌的请求。不要用真实登录会话冒险直连。单独的 `Failed to fetch`、超时、403、一次代理成功都不能证明全部防直连覆盖。

答复先说：当前规则是否存在、范围是什么、是否启用。随后按本次证据说明配置验证、连接验证及覆盖边界。报告成功时给新鲜核验；查询失败时明确“无法确认”，不推断已删除。失败已修复后区分历史失败和当前状态。

规则又消失时，转到排查参考，寻找事件时间和修改程序。不要反复重建、自动停服务或声称发现恶意软件。
